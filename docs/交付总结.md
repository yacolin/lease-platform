# lease-platform 1.0 交付总结

> 生成日期：2026-08-31 ｜ 版本：1.1.0 ｜ 状态：**P0~P6 全部完成 + 1.1 会议室定价模型，测试全绿**
> 相关文档：`README.md`（快速开始/接口一览）、`docs/接口规范.md`（接口约定）、`db/README.md`（表与主键策略）、`db/migrations/README.md`（迁移）

## 1. 项目概述

园区/企业服务平台（1.0），围绕企业员工日常消费场景：**咖啡点单、正餐预订、会议室预约、充值余额与会员折扣**，覆盖微信小程序（用户端）与管理后台（商家端）。

| 维度 | 选型 |
|---|---|
| 语言/框架 | Java 21 + Spring Boot 4.1.1 |
| 数据库访问 | MyBatis-Plus 3.5.17（雪花 ID + 分页插件） |
| 数据库 | MySQL 8（`lease_db`，21 张表，db SQL 与 Flyway 双轨） |
| 缓存/会话 | Redis（refresh token 会话、Lettuce） |
| 安全 | Spring Security（无状态 + JWT Bearer + 双端类型隔离） |
| 认证 | 双登录：管理端 username/password（bcrypt）、小程序微信 code（开发 mock） |
| 支付 | 余额账本（赠送优先扣）+ 微信支付结构就绪（JSAPI/回调/查单，未配置时 mock 直充） |
| 接口文档 | springdoc-openapi（Swagger UI + 按端分组 JSON，可生成前端请求文件） |
| 构建/部署 | Maven + Docker（docker-compose：MySQL+Redis+app）+ Flyway 自动迁移 |
| 测试 | **281 例**：单测（Mockito）+ Web（@WebMvcTest）+ 集成（真实 MySQL/Redis） |

## 2. 功能全景（P0~P6）

### P0 认证与用户基础 ✅
- JWT 认证过滤器（Bearer → 校验签名/过期 → SecurityContext；access 2h / refresh 7d）
- 双登录：`/api/v1/auth/login`（管理端 admin/123456，bcrypt，`usr_admins`）、`/api/v1/auth/wx-login`（小程序，开发 mock 固定 openid）
- 刷新/登出（refresh token 存 Redis，`auth:refresh:{userType}:{userId}` 复合身份防串号）
- `GET/PUT /api/v1/me`（资料/余额/会员等级）

### P1 企业域 ✅
- 实名注册（注册人即企业管理员，audit_status=0）→ admin 审核（通过/拒绝，拒绝必填原因并释放关联）
- 员工管理：按手机号邀请/接受/拒绝/移除/设置管理员（`usr_enterprise_members` 状态机）
- 会员等级购买：公开等级列表 / 下单 / mock 支付生效（企业等级+到期时间+员工同步）

### P2 交易域 ✅
- 充值档位（public 列表 + admin CRUD）
- 充值下单 + **mock 直充**（settleRecharge 事务幂等，乐观更新防并发重复入账）；微信 JSAPI/回调/查单结构就绪（WechatPayClient，未配置降级）
- 余额账本 `BalanceService.credit/debit`：余额+赠送余额增减、流水前后值、事务；消费赠送优先扣

### P3 咖啡点单 ✅
- 商品+规格快照下单 → `ord_orders` + `ord_order_items`
- **折扣叠加**：应付 = 原价 × 会员折扣率 × 充值折扣率（DiscountCalculator 共享）
- 余额支付（赠送优先）→ 待取餐 + 6 位取餐码 → 商家推进/核销/取消退款
- 我的订单 / 商家订单管理（筛选 + 统计）

### P4 正餐预订 ✅
- 菜单运营：整单配置（batch）/复制（copy）/按日清空
- 按日期+时段（午餐/晚餐）预订套餐：配送方式（自取/楼内/周边 500 分）、套餐+当天菜品快照
- 规则校验：提前 1 天（晚 8 点后最早后天）、可订未来 3 天；备餐流转（1→2→3，1/2→5 退款）

### P5 会议室域 ✅
- 会议室 public 列表 + admin CRUD
- 预约：时段冲突校验（409）、会员免费时长抵扣（`monthly_meeting_hours` 按预约月统计）、超时计费（超出 × 超时单价，见下「1.1 定价模型」）、价格快照
- 状态流转：待确认（付费）→已确认→已完成/已取消（退款）/惰性过期；按月查询剩余免费时长

### 1.1 会议室定价模型 ✅（「预约规则/会员等级定价」共享对话落地）
- `mtg_rooms.hourly_fee` 删除：超出费用不再由会议室持有，避免与 `usr_member_levels.meeting_overtime_fee` 冲突（价格调整只改数据、新等级扩展不动表结构）
- 新增 `mtg_room_level_prices`（会议室 × 会员等级 超出费用覆盖价，`uk_room_level` 唯一）+ 管理端 CRUD（`/api/v1/room-level-prices/**`）
- **计费取值**：会议室覆盖价 → 等级默认价（`usr_member_levels.meeting_overtime_fee`，非会员按 BASIC 兜底）
- **价格快照**：预约表新增 `overtime_unit_price`（下单时单价）+ `free_hours_deducted`（抵扣免费时长），规则可改、快照不变，历史单可对账
- 配套：Flyway V5 迁移、db/04_mtg.sql、seed.py（7 条覆盖价演示数据）

### P6 系统域与工程化 ✅
- 通知中心：站内通知列表/未读数/已读（微信模板消息预留）
- 操作日志：`@OperationLog` 注解 + AOP 切面（操作人/类型/参数/IP/UA，成功失败均记录）
- 环境分离：application-dev/prod（敏感项环境变量化）
- **Flyway**：迁移脚本 V1~V4，`FlywayMigrationRunner`（Boot 4 无自动配置，Java API 驱动）prod 自动迁移
- **Docker**：Dockerfile + docker-compose（MySQL+Redis+app）一键部署

## 5. 关键设计决策

| 决策 | 说明 |
|---|---|
| 双轨模式 | 同一实体"对外浏览（`/api/v1/public/**`，只读+强制过滤可见状态）"与"管理端（CRUD+admin-paths）"两套独立实现，权限/数据可见性天然隔离（规范见 `docs/接口规范.md`） |
| 双端类型隔离 | 管理端接口仅 `user_type=1`（ROLE_ADMIN）放行，小程序用户 403 |
| 折扣模型 | 应付 = 原价 × 会员折扣率 × 充值折扣率（叠加）；`member_discount`/`recharge_discount` 分别记账，明细折后小计恒等 |
| 赠送余额优先扣 | 消费/支付时赠送余额优先抵扣（营销导向），退款入余额（总资产不变） |
| 支付幂等 | 充值/订单入账统一"状态乐观更新（0→1）+ 流水"事务，并发重复回调不重复入账 |
| 微信支付降级 | `wechat.pay.*` 未配置（开发默认）走 mock 直充；配置完整后自动启用 JSAPI/回调/查单，无需改业务代码 |
| 复合身份会话 | 管理端/小程序 id 空间独立，Redis refresh key 带 userType 防串号 |
| Flyway 自驱动 | Spring Boot 4 移除 Flyway 自动配置 → `FlywayMigrationRunner`（Java API）prod 启动自动迁移 |
| 惰性状态推进 | 会议室过期、会员等级过期等用查询时惰性降级，避免定时任务 |
| 定价模型（1.1） | 超出费用按「会议室覆盖价 → 等级默认价（非会员按 BASIC 兜底）」解析，价格调整只改数据、新等级扩展不动表结构；预约表存价格快照（单价+抵扣时长）保证历史单可对账 |

## 7. 运行与部署

**开发**：
```bash
make db-reset   # 建库 + 20 表 + 种子数据
make run        # http://localhost:8080（Swagger UI: /swagger-ui.html）
make test       # 281 例
```

**生产（Docker 一键）**：
```bash
cp .env.example .env   # 填写 DB_PASSWORD / JWT_SECRET 等
docker compose up -d --build
# 应用 prod profile 启动，Flyway 自动建表 + 种子；管理端 admin / 123456
```

**直接运行**：`SPRING_PROFILES_ACTIVE=prod java -jar app.jar`（需先设置 DB_URL/DB_PASSWORD/JWT_SECRET 等环境变量）。

## 9. 遗留与后续建议

1. **微信支付真实接入**：配置 `wechat.pay.*` 后 JSAPI 下单/回调/查单自动启用；充值/会员购买由 mock-pay 切换到回调入账（`WechatPayClient` 已就绪）。
2. **微信模板消息**：`NotificationService.send` 已留 template_id 入口，接入真实发送即可。
3. **前端工程**：按 `/v3/api-docs/admin|public` 生成请求文件（`utils/request.js + api/*.js` 模式），小程序与后台分别接入。
4. **生产加固**：JWT 密钥轮换、管理端密码强制修改、Redis 密码、CORS 域名收紧、操作日志归档。
5. **可观测性**：接入 actuator 指标/日志采集（ELK 或云监控），日志表考虑按时间分区。
